📦 Part 1: CSS Architecture (style.css)

Source: style.css

.container {
    width: 960px;
    height: 960px;
    display: flex;
    flex-wrap: wrap;
}

.grid-square {
    box-sizing: border-box;
    border: 1px solid #ddd;
    flex: 0 0 calc(100% / 16);
    aspect-ratio: 1;
}

.container

Canvas Host
  • width: 960px; & height: 960px;

    Concept: Fixed 1:1 Canvas Constraints.

    Why this choice? The Odin Project specifies a fixed width of 960px. Matching width and height guarantees a rigid square drawing canvas that never distorts or changes size when the user alters the resolution to 16, 50, or 100 squares per side.

  • display: flex;

    Concept: Flexible Box Model (Flexbox).

    Why this choice? Standard <div> elements are block-level and stack vertically. Flexbox allows children to align horizontally across the main axis without floats or inline-block whitespace artifacts.

  • flex-wrap: wrap;

    Concept: Multi-row Flow Breaking.

    Why this choice? By default, Flexbox squeezes all children onto one single row (nowrap). wrap instructs the layout engine: "Once squares fill 100% of the row width, break down to the next row." This automatically creates our 2D grid matrix.

.grid-square

Cell / Pixel
  • box-sizing: border-box;

    Concept: The CSS Box Model.

    Why this choice? Under the default content-box, borders are added on top of width (width + 2px). 16 squares with borders would total over 100%, causing the last item on every row to wrap prematurely. border-box forces the 1px border to be absorbed inside the item's percentage calculation.

    ❌ content-box

    60px width + 2px border = 62px.
    Overflows 100% and breaks the grid alignment.

    ✅ border-box

    Width = 60px total.
    (58px content + 2px border inside). Perfect fit.

  • border: 1px solid #ddd;

    Concept: Subtle Pixel Matrix Guides.

    Why this choice? Defines visible pixel boundaries with a soft light-gray color (#ddd), allowing the user to discern individual drawing units without overwhelming visual noise.

  • flex: 0 0 calc(100% / 16);

    Concept: Flex Item Sizing Shorthand (grow, shrink, basis).

    Why this choice?

    • flex-grow: 0 → Prevents squares from stretching to fill empty space.
    • flex-shrink: 0 → Prevents squares from being squished smaller.
    • flex-basis: calc(100% / 16) → 6.25% per square. Exactly 16 squares = 100%.

  • aspect-ratio: 1;

    Concept: Responsive Geometric Aspect Ratio.

    Why this choice? Guarantees that height always matches the dynamically computed width (1:1). As JavaScript alters the square's width percentage, the height scales in lockstep automatically without requiring manual height calculations in JS.

⚡ Part 2: JavaScript Logic (script.js)

Source: script.js

const container = document.querySelector(".container");
const btnSize = document.querySelector(".btn-size");

function getRandomColor() {
    const r = Math.floor(Math.random() * 256);
    const g = Math.floor(Math.random() * 256);
    const b = Math.floor(Math.random() * 256);
    return `rgb(${r}, ${g}, ${b})`;
}

function createGrid(size) {
    container.replaceChildren();

    const fragment = document.createDocumentFragment();
    const squarePercentage = `${100 / size}%`;

    for (let i = 1; i <= size * size; i++) {
        const square = document.createElement('div');
        square.classList.add('grid-square');
        square.style.flex = `0 0 ${squarePercentage}`;
        square.style.opacity = "0.1";
        fragment.appendChild(square);
    }
    container.appendChild(fragment);
}

container.addEventListener("mouseover", (event) => {
    const square = event.target;
    if (!square.classList.contains("grid-square")) return;

    if (!square.style.backgroundColor) {
        square.style.backgroundColor = getRandomColor();
    }

    const currentOpacity = parseFloat(square.style.opacity) || 0;
    if (currentOpacity < 1) {
        square.style.opacity = (currentOpacity + 0.1).toFixed(1);
    }
});

btnSize.addEventListener("click", () => {
    const input = window.prompt("Enter number of squares per side (max 100):");
    if (input === null) return;

    const size = parseInt(input, 10);
    if (isNaN(size) || size < 1 || size > 100) {
        alert("Please enter a valid number between 1 and 100.");
        return;
    }

    createGrid(size);
});

DOM Selectors & getRandomColor()

Setup & Math
  • const container = document.querySelector(".container");
    const btnSize = document.querySelector(".btn-size");

    Concept: DOM Caching.

    Why this choice? Storing DOM references in const variables query the DOM once upon load. Querying inside loops or event handlers would force the browser engine to search the DOM tree on every mouse move, hurting performance.

  • Math.floor(Math.random() * 256)

    Concept: Uniform Pseudo-random Integer Generation.

    Why this choice? Math.random() generates a floating-point number in the range [0, 1) (inclusive of 0, exclusive of 1). Multiplying by 256 produces [0, 255.999...]. Math.floor() chops off the decimal, giving clean integers from 0 to 255, perfectly covering the 8-bit RGB color channels.

  • return `rgb(${r}, ${g}, ${b})`;

    Concept: ES6 Template Literals.

    Why this choice? Cleaner and less error-prone than legacy string concatenation ("rgb(" + r + ", " + g + ", " + b + ")"). Note: CSS color syntax is strict; ensure no trailing commas are left inside the parentheses.

DOM Performance
  • container.replaceChildren();

    Concept: Atomic DOM Reset.

    Why this choice? Modern method to wipe all child nodes instantly without triggering the HTML parser overhead of container.innerHTML = "". Avoids memory leaks from detached nodes.

  • const fragment = document.createDocumentFragment();

    Concept: Off-screen Virtual Subtree (DocumentFragment).

    Why this choice? At 100×100 squares, the loop creates 10,000 DOM elements. If you call container.appendChild() inside the loop, the browser triggers 10,000 layout recalculations (reflows & repaints). Appending to a DocumentFragment builds everything off-screen in memory. On line 24, a single container.appendChild(fragment) paints all 10,000 squares in one single frame.

    ⚡ Hardware Efficiency: DocumentFragment cuts DOM generation time from seconds down to milliseconds.
  • square.style.flex = `0 0 ${squarePercentage}`;

    Concept: Dynamic Inline Style Injection.

    Why this choice? Calculates the exact width share per square (e.g. 100 / 16 = 6.25%, or 100 / 64 = 1.5625%). Combined with aspect-ratio: 1 in CSS, the height adapts automatically.

  • square.style.opacity = "0.1";

    Concept: Progressive Darkening Baseline.

    Why this choice? Initializing opacity to 0.1 (10%) keeps the grid lines faintly visible on initial load while starting the 10-step darkening progression on first touch.

container.addEventListener("mouseover", ...)

Event Delegation
  • container.addEventListener("mouseover", (event) => { ... });

    Concept: The Event Delegation Pattern.

    Why this choice? Rather than attaching 10,000 individual event listeners to every square, we attach one single listener to the parent container. As mouse events bubble up through the DOM tree, the container catches them. This drastically cuts RAM usage and survives grid rebuilds without listener cleanup.

  • if (!square.classList.contains("grid-square")) return;

    Concept: Guard Clause / Event Target Filtering.

    Why this choice? Ensures hovering over the container background or gaps does not accidentally recolor the entire container itself.

  • if (!square.style.backgroundColor) { square.style.backgroundColor = getRandomColor(); }

    Concept: Sticky Random RGB Assignment.

    Why this choice? Checks if the square has already been tinted. If empty, it assigns a permanent random RGB color on the first interaction, preserving that hue for subsequent darkening passes.

  • square.style.opacity = (currentOpacity + 0.1).toFixed(1);

    Concept: Incremental Darkening & Floating-Point Sanitization.

    Why this choice? In binary floating-point arithmetic, 0.1 + 0.2 = 0.30000000000000004. toFixed(1) rounds and formats the number to one decimal place (0.1, 0.2, ..., 1.0), ensuring clean CSS values and reaching full opacity in exactly 10 passes.

Input Validation
  • if (input === null) return;

    Concept: Cancellation Escape Hatch.

    Why this choice? When a user presses "Cancel" in window.prompt(), the browser returns null. Without this guard clause, parseInt(null) would trigger an unwanted error alert instead of gracefully closing the prompt.

  • if (isNaN(size) || size < 1 || size > 100)

    Concept: Defensive Input Sanitization & Bounds Checking.

    Why this choice? Never trust user input. Without a maximum ceiling (100), entering 1000 would attempt to create 1,000,000 DOM nodes and instantly lock up the user's browser tab.

  • createGrid(16);

    Concept: Initial Default State.

    Why this choice? Bootstraps the application on first page load with the canonical 16×16 grid before any user button interaction occurs.
